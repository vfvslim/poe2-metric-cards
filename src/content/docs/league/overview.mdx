## 业务问题 BUSINESS QUESTION

What are PoE2 league / season cumulative KPIs so far for the active league, by country and platform?

## 指标定义

League overview KPIs in `app_poe2_league_overview` (season-window **cumulative**, not normal daily DAU).

## 计算公式

DAG provides `league_name`, `start_date`, `end_date`. SQL aggregates daily tables inside that league window up to the as-of date.

Selected fields:

- Activity / `new_users`: from active overview over league dates so far
- `max_dau`: max daily active in window
- `return_user`: `return_users` − `new_users`
- `d30_dau`: avg DAU over first 30 days of league
- `ingame_revenue`: `sum(pay_amount) / 100` from pay flat over league window
- `avg_d1_retention`: avg D1 retention under league logic

## 口径要素

### 分子 Numerator

Depends on field:

- Activity fields from `app_poe2_active_overview_d`
- `ingame_revenue` from `app_poe2_pay_flat_d.pay_amount / 100`
- Retention from register-retention logic in the league window

### 分母 Denominator

None.

### 粒度 Grain

One row per `dtstatdate` (as-of date), `league_name`, `country_code`, `os`.

Values are generally **cumulative within the league window**.

## 过滤条件 FILTERS

- `dtstatdate = '{{ ds }}'`
- League window: `start_date` to `end_date` from DAG XCom / league info
- Aggregate only dates inside that league window and `<= dtstatdate`

## 维度

- `dtstatdate`
- `league_name`
- `country_code`
- `os`

## 踩坑与注意 CAVEATS

- Always name the **league / window**.
- League cumulative actives ≠ normal daily DAU. See [DAU](/poe2-metric-cards/core/dau/).
- League `ingame_revenue` = in-game MTX in the league window, **not** platform / store revenue. See [In-game pay](/poe2-metric-cards/core/ingame-pay-amount/) and [Platform net revenue](/poe2-metric-cards/core/platform-net-revenue/).

## SQL 模式

Resolve active league dates → aggregate daily active / pay / retention tables within the window → write `app_poe2_league_overview`.
